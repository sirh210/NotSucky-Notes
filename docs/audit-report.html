Production readiness audit

NotSucky Notes A desktop app that could not start, and what it took to fix that

Audited v1.0.0 Delivered v1.3.0 Date 2026-08-10 Stack Python 3.10+ · PySide6 Scope app · persistence · packaging · tests · docs

The audited version could not start. card_widget.py raised ImportError at import time, and the dashboard imports it on every grid refresh — including the one in its own constructor.

Behind that blocker sat a second one (NameError on QSizePolicy), and behind those, a storage layer pointed at a directory the user's notes were not in. The test suite caught none of it: 8 tests failed and 7 errored before this audit, there was no GUI coverage at all, and the tests that did run were reading and writing the real notes directory.

01

The application could not run

Blocker

1.1 QMouseEvent imported from the wrong Qt module

card_widget.py:8 — from PySide6.QtCore import Qt, QMouseEvent, Signal. QMouseEvent lives in QtGui. This raised ImportError the moment anything imported the module, which DashboardWindow._refresh_grid does unconditionally. The application was 100% non-functional.

1.2 QSizePolicy used but never imported

card_widget.py:40 called setSizePolicy(QSizePolicy.Expanding, …) with no import — a second, independent hard failure sitting immediately behind 1.1.

1.3 Invalid PEP 517 build backend

build-backend = "setuptools.backends._legacy:_Backend". No such module. pip install . and any wheel build failed outright.

1.4 Four subpackages had no __init__.py

models/, services/, utils/ and views/ resolved in a source checkout only through implicit namespace packages. packages.find had no include filter, so it would have swept in tests and notes while an install missed the real code.

FixedCorrect imports, setuptools.build_meta, __init__.py in every subpackage, include = ["notsucky*"]. Verified by building a wheel and importing all subpackages from a clean virtualenv.
02

Data loss and data location

Critical

2.1 Notes were stored where the user could not see them

PROJECT_ROOT = Path(__file__).resolve().parent.parent resolves to the package directory, not the project root — so NOTES_DIR became notsucky/notes while the real notes sat in ./notes. The dashboard would have come up empty. Installed, it would have written notes into site-packages, where the next upgrade deletes them.

2.2 A third, CWD-dependent location

main.py:12 ran os.makedirs("notes") at import time — relative to the working directory, and disagreeing with 2.1.

2.3 The path could not be overridden consistently

file_manager.py bound NOTES_DIR at import while note.py resolved it lazily on purpose ("to support testing monkeypatches"). The two disagreed under any override: save_note wrote to the patched directory while load_by_id, load_all and delete_note used the original. This is why the baseline tests both failed and touched real user data.

FixedOne resolver in utils/paths.py — explicit override → NOTSUCKY_NOTES_DIR → per-platform user data directory — called as a function everywhere. A one-time copy migration imports notes from either legacy location; originals stay put as a backup and a marker file stops it re-running. Verified end to end: both real notes were imported and rendered.

2.4 Writes were not atomic

open(path, "w") truncates before writing. A crash, power loss or full disk mid-write destroyed the note — and the loader then discarded the wreckage as "corrupt".

FixedTemp file in the same directory → fsync → os.replace. A failed write now leaves the previous version completely intact, covered by a test that injects an OSError into os.replace.

2.5 Save failures were invisible

Errors were logged and swallowed, so the user kept typing into a note that was no longer reaching the disk. StorageError now propagates to the view; the note shows ⚠ not saved and the dashboard status bar shows why.

2.6 No path-traversal guard on note ids

Ids became file names with no validation — a hand-edited file with "id": "../../.bashrc" would be written outside the notes directory. Ids are now validated against [A-Za-z0-9_-]{1,64}, repaired on load, and rejected in path_for.

03

Functional defects

High

3.1 Runaway window drag — visible in your saved data

Each mouse-move re-applied a delta measured from the original press without re-anchoring, so the offset compounded. The proof was sitting in the repository:

notes/505e8a20.json { "title": "78Skies", "x": -45088, "y": 33945 }

And because saved positions were restored with no bounds check (3.2), that note opened roughly 45,000 px off-screen and could never be reached again.

FixedThe drag anchors on the cursor-to-origin offset, which is constant and cannot compound; position is clamped to the real screen layout on restore and on release. That note now opens on screen — verified.

3.3 Notes could not be dragged at all

The drag was guarded by not self.childAt(event.pos()). That is inverted: a press only reaches the window handler when a non-interactive child ignored it — which is exactly when childAt is non-None. The guard rejected precisely the presses that should drag.

FixedAn explicit drag-handle test that walks up from the child under the cursor and refuses only genuinely interactive controls. The title field stretches across the whole bar and left almost nothing to grab, so a dedicated ⠿ handle was added.

3.4 Notes could not be resized

The window is FramelessWindowHint, which removes the native resize border, and nothing replaced it — despite the README promising "resize freely". The model had no width/height fields either, so any size would have been lost on close. Now: a QSizeGrip plus persisted width/height.

3.5 Auto-save was not debounced

QTimer.singleShot(1000, …) fired on every textChanged. Typing 200 characters scheduled 200 timers and produced 200 full-file writes a second later; the title had no debounce at all — one disk write per keystroke. Replaced with one restartable timer per window, covered by a test asserting zero writes mid-burst.

3.6 Cards rendered with no background

A QWidget subclass ignores background-color in its own stylesheet unless WA_StyledBackground is set. The v1.0 refactor turned the card from a plain QWidget into a subclass and inherited this: every card painted transparent, leaving pale text on the dark dashboard.

No logic test could see this. It was found by running the app and looking at it — and is now pinned by regression tests that assert real pixel colors.

3.7 – 3.10 Four state bugs around minimize and delete

  • The dock was never restored at startup — _minimized_ids was not populated from the persisted flags, stranding minimized notes.
  • Restore never cleared the flag, so a restored note stayed minimized: true on disk forever.
  • Hidden windows leaked and duplicated — the open-note check required isVisible(), so a minimized note got a second widget that orphaned the first.
  • Deleting an open note resurrected it — cleanup also required isVisible(), so a hidden widget survived deletion and the next auto-save wrote the note straight back to disk.
FixedDock rebuilt from disk and pruned of missing notes; restore clears the flag in memory, on disk and in the dock; a _live_widget helper drops dead references; deletion tears the window down with signals blocked before removing the file. Each has a named regression test.

3.11 The dashboard never closed its note windows

There was no closeEvent. Note windows are top-level Qt.Tool windows, so closing the dashboard left them alive — keeping the process running and losing every unflushed edit.

3.12 Advertised drag-to-reorder did not exist

The README and the pyproject.toml description both promise a "drag-to-reorder grid". CardWidget called setAcceptDrops(True) and implemented no drag or drop handlers at all.

BuiltCards are now drag sources and drop targets with a dashed drop indicator; an order field persists the arrangement, sorted with recency as the tie-break. Reordering is refused while a filter is active, since positions derived from a filtered subset would scramble the full list.

3.13 Non-deterministic note placement

Placement used hash(note.id). Python salts string hashing per process, so an unpositioned note landed somewhere different on every launch, with nothing keeping it on screen.

05

The test suite was reporting confidence it had not earned

Critical
  • 8 failures and 7 errors at baseline — none of them the tests correctly reporting an app bug; they were defects in the tests themselves.
  • test_search_by_title asserted results[0].title == "Note Python Notes" — a value the code could never produce.
  • test_note_service.py monkeypatched note_module.NOTES_DIR, an attribute that does not exist on that module, erroring out all 7 tests in the file.
  • conftest.py created tests/__init__.py as a side effect of collection.
  • Tests read and wrote the real notes directory. Running pytest put the user's data at risk.
  • Zero GUI coverage — which is exactly why two import-time blockers shipped.

Delivered: 443 tests at 92% coverage, isolated by an autouse fixture that repoints storage at a per-test temporary directory. GUI tests via pytest-qt cover the grid, filtering, the dock, the full open/close/minimize/restore/delete lifecycle, drag-to-reorder, debounced saving, storage-failure reporting, off-screen clamping, and the pixel-level background regression. Named regression tests exist for 3.1, 3.3, 3.6, 3.7, 3.8, 3.9 and 3.10.

06

Removed code

Cleanup

A 22 KB main.py in the repository root was a copy of the original single-file "Sticky Notes v6", fully superseded by the package and still being shipped. It had its own fatal bugs — QGridLayout.rowWidget() and columnWidget() do not exist in Qt, event.mimeData.data(…) is missing a call, drag.exec_() is the removed Qt5 spelling, and QDrag was never imported — so its drag-to-reorder raised on first use. It also accounted for 68 of the 104 lint errors.

Moved to archive/ rather than deleted, because there is no version control to recover it from. _dump.py and _dump.py.tmp went with it. The directory is excluded from linting and from the wheel.

07

Recommendations — all implemented

Done
  1. Version control. Committed and pushed to sirh210/NotSucky-Notes. The superseded monolith went into the first commit so git holds a copy, then out in the commit after — recoverable from history, absent from the tree.
  2. CI. Lint, types, and a dependency audit, then the suite on Linux and Windows across Python 3.10–3.13, then a wheel build that installs into a clean virtualenv and imports every subpackage — exactly the failure of 1.4. Coverage below 90% fails the build.
  3. Undo for deletion. Notes move to .trash and Ctrl+Z restores the last one. The 30-day sweep this originally shipped with was removed in 1.3.0 — see section 09. The deletion time lives in the file name rather than the mtime, which sync tools do not preserve.
  4. Backups. Dated zip snapshots beside the notes, at most one a day, ten kept, built under a .part name so a partial file is never mistaken for a usable one.
  5. Application icon. Drawn at runtime at seven sizes — no binary asset, no scaling blur.

8.3 A rendering bug the unit tests could not see

Found while checking the performance work visually: a selector-less stylesheet — setStyleSheet("background: transparent") — applies to the widget and every descendant. The grid container was doing exactly that, blanking the background of every card inside it.

8.4 Types, observability, and tested documentation

mypy now runs in CI, and its findings were real: QApplication.instance() can be a QCoreApplication with no stylesheet, QLayout.takeAt can return None, and is_valid_id is now a TypeGuard so the check and the type cannot drift apart.

Qt warnings route into logging, uncaught exceptions are logged and reported, startup steps are timed, and --diagnostics prints a support report carrying no note content. tests/test_docs.py fails when the docs describe a module, shortcut, flag, or path that does not exist — it caught three stale claims in the README on its first run.

09

Two guarantees, and the three things that broke them

1.3.0

Asked to make certain the application never deletes a note and never asks anyone to sign in, I checked rather than answered. The sign-in half was already true. The no-deletion half was not — and two of the three culprits were mine, introduced by earlier work in this very audit.

9.1 A sweep deleted trashed notes on every launch

The trash added in 1.1.0 came with a 30-day retention sweep that ran at startup. That is unattended, unprompted deletion of a user's own data — the application deciding on its own that something had been in the bin long enough.

RemovedRetention is unlimited. TRASH_RETENTION_DAYS is None, purge_trash() with no argument removes nothing, and startup maintenance no longer calls it at all — it is now additive only.

9.2 A length limit quietly amputated long notes

Note.__post_init__ capped content at 1,000,000 characters while reading a file. Nothing looked wrong — until the next save wrote the shortened value back. And the next save could be triggered by nothing more than moving the window.

The same pattern hid in two more places: the editor's setPlainText and QLineEdit.setMaxLength, which both truncated an over-limit note the instant its window opened.

FixedNothing truncates on load or save. Limits now bound how far new input can grow a note: each note carries a ceiling of max(limit, current length), so typing is still bounded while existing text is untouchable. Memory is protected by refusing to read an oversized file — which leaves it intact on disk — rather than by discarding text already in memory.

9.3 Proving it, rather than asserting it

Simulated 365 launches against a store holding a 1.5-million-character note, a note trashed ten years ago, a corrupt file, and a stray non-note file:

seeded 8 files after 365 launches: 8 files files lost : NONE files shrunk : NONE long note : 1,500,000 chars (seeded 1,500,000) after a save : 1,500,000 chars 10y-old trash: restored=True

Unreadable and oversized files are skipped and left exactly where they are, never tidied up. The only thing that removes a note is the user.

No sign-in is structural, not a promise. The package imports no networking library at all — no socket, ssl, http, urllib or requests, and of Qt only QtCore, QtGui and QtWidgets. One test walks the AST of every module and fails on any such import; another runs a full session with socket.socket patched to raise. There is nothing to authenticate to, so there is no credential to phish, leak or store.

10

This page, audited against its own checklist

Meta

The application is Qt, not web — it contains no HTML, CSS or JavaScript at all. This report does, so the front-end checklist was applied here instead. Two findings came out of it that were not merely box-ticking.

10.1 Two palette tokens failed WCAG AA

Converting the palette to oklch() meant computing every value properly, and the contrast audit that came with it caught two failures in text I had already shipped: --ink-faint at 3.39:1 and the light --accent at 4.24:1, both used for small uppercase labels that need 4.5:1.

FixedBecause OKLCH lightness is perceptual, each was corrected by moving L alone — hue and chroma untouched, so the palette still looks like itself. Now 4.63:1, 4.61:1 and 4.62:1.

10.2 Cascade layers would have silently broken the page

The host wraps this document and injects its own reset — body{font:14px…;background:#faf9f5;color:#141413} — as unlayered CSS. Unlayered declarations beat every layer regardless of order, so moving everything into @layer would have handed the host's light background and 14px type to a page rendering its own dark theme.

FixedEverything is layered except the body and color-scheme rules, which stay unlayered deliberately so they outrank the host. Verified in a browser against a replica of the real wrapper, in both themes.

10.3 What the rest of it bought

  • Subgrid earns its place in the scoreboard: each tile spans three parent rows, so the label, the old value and the new value align across every tile even when one label wraps. Measured — all four "after" values land on the same pixel row.
  • :has() marks a finding that carries its own fix as resolved, with no extra class in the markup. It asserts only the positive: several findings share one fix block with their siblings, so a missing badge means nothing, and styling those as "open" would have been false. An earlier version did exactly that and was caught on screen.
  • @property types the colour tokens — and, more usefully, makes them animatable, which is what lets the theme swap cross-fade in pure CSS.
  • Container queries reflow a finding when its own column narrows rather than when the window does, so the component stays correct wherever it is placed.
  • View Transitions is declared for the standalone page, but honestly: inside the artifact frame there is no navigation to animate. The user-visible outcome the rule is after — a smooth transition between page states — is delivered by the animated tokens above, and it respects prefers-reduced-motion.
